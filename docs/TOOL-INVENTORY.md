# OpenNeko tool inventory for Harness

Source snapshot: `packages/llm/src/work/agent-core.ts`, `work/tools.ts`,
`work/interaction-server.ts`, `workflows/{builder,rule-builder,action,output}-server.ts`
on `feat/openneko-harness`, reviewed 2026-09-28. Names below are logical MCP
`server.tool` names; the Go catalog uses pinned aliases such as
`mcp_neko_records_find_records`. A discovered MCP tool is never admitted by
discovery alone. “Excluded” means the Harness bridge and broker deny it, while
Hermes can retain its existing path.

| Surface | Logical tools / capability | Harness status and recovery boundary |
| --- | --- | --- |
| Business data | GraphJin server agent and its catalog/query tools | `lookup` delegates to the host GraphJin agent; each call is host-journaled. Direct GraphJin MCP calls are excluded. |
| Records | `neko_records.browse_catalog`, `browse_blueprints`, `find_records`, `get_record`, `find_recycled_records`, `get_recycled_record`; governed `record_*` action descriptors | Reads passed actor-bound GraphJin, MCP, OpenShell and Ax. Queued Work runs qualified create, update, soft-delete and restore against seeded Records GraphJin data. Worker preflight and human approval preceded each effect; duplicate delivery reused the result. Withheld Harness or Records receipts were reconciled from the engine receipt and audit without dispatching a second write. |
| Knowledge | `neko_memory.search`, `neko_library.search`, `neko_memory.save` | Search is admitted through the MCP bridge for customer Work runs. The equivalent `memory_save` direct capability is admitted only for customer Work runs and records a host effect receipt before Go checkpoint publication. An ambiguous save remains unknown and is never redispatched. The MCP `save` route remains excluded. |
| Interaction | `neko_interaction.ask_user_question`, `neko_ui.render_cards` | Admitted for eligible Work turns. Question pause/answer and validated card events passed connected worker/OpenShell checks. The completed Work card rendered once before and after a real Chromium reload. |
| Skills and local files | `neko_skills.create_skill`; Harness `skill_create`, `skill_inspect`, `skill_update`, `skill_read`, `file_read`, `file_edit`, `file_write`, `file_search`, `upload_read`, `upload_search` | Current-admin, host-journaled skill creation and whole-tree versioned update passed connected Ax/OpenShell and production queue turns; later runs read each published version. Redelivery did not repeat the model or host write, and Chromium showed each answer once after reload. An interrupted directory swap is recovered before customer Work staging. Read-only staged skill and upload tools and run-artifact file tools passed connected turns; Go file writes require a matching read version or create-only target. |
| Workflow and rule definition | `neko_workflow_builder.create_workflow`, `list_workflows`, `delete_workflow`; `neko_rule_builder.save_rule`, `list_rules` | Actor-filtered workflow and rule lists are pinned MCP reads. Direct `workflow_save` admits cron/batch and data-change/watch create and edit for customer Work; the latter preflights through actor-bound GraphJin reads and commits definition and trigger rows together. Direct `rule_save` admits current-admin create and edit. Save tools require create-only or exact listed-version preconditions, host journaling and persisted cards. Direct `workflow_delete` requires a current-run user confirmation, enabled actor and exact listed ID/name/version; connected queue and Chromium checks passed. The separately versioned workflow batch executor is a queued API/workflow path, not a skill or model tool. |
| Workflow execution | `neko_action.request`, `neko_workflow_output.emit` | Queued Harness workflow turns can emit typed outputs and propose ready, held pack actions through direct, host-journaled operations bound to the exact workflow/run. Proposals await human approval; the broader MCP action surface is not admitted. |
| Integration action | Dynamic `neko_plugin_actions.*`, `neko_pack_actions.*` | Held, unambiguous kinds enter a bounded run-bound `propose` lane; policy scope is fixed by the host descriptor. Harness advertises a native pack kind only when its worker executor is registered as `pack`, or a declared GraphJin API operation has the supported declarative adapter. Pack, plugin and internal approvals resolve only same-source executors. The full connected suite passed synthetic HTTP effect recovery, installed-plugin approval/effect, workflow pack approval and Records writes. A separate connected queue gate exercised the real declarative pack adapter against a local GraphJin-compatible HTTP endpoint: one approved provider call and receipt, then a committed call with a lost response that remained unknown without redispatch. External installed-plugin provider effects still need a connected gate. Plugin auto execution remains excluded. |
| Administration | `neko_plugin_manager.list_plugins`, `request_plugin_install`, `request_plugin_uninstall`; `neko_user_manager.list_users`, `request_user_change`, `list_groups`, `request_group_change`, `request_item_grant`, `request_data_access_change`; `neko_channel_manager.list_channels`, `request_channel_change`; `neko_data_source_manager.list_data_sources`, `request_data_source_change`; `neko_rule_builder.list_rules`; `neko_source_config_manager.describe_source_graph`, `list_source_secret_names`, `ask_graphjin_config_agent`, `import_openapi_spec`, `list_openapi_specs`, `request_source_config_change`; `neko_audit.audit_trail` | Six list catalogs for plugins, users, groups, channels, data sources and rules are pinned reads for customer Work turns; a queued OpenShell/worker run exercised all six. The separate audit read is host-gated on the bound admin actor and org. Source graph, source secret **names** and imported OpenAPI asset metadata are feature-gated admin reads; a queued run exercised all three, and a member was denied. Member invitation, nonadministrator deactivate/reactivate and promotion, group creation, custom-group add_member and disabled data-source registration use run-bound internal proposals, human approval and worker effects; connected queue and browser gates verify actor/target recheck and one effect on redelivery. Administrator lockout-sensitive changes and other group, channel, data-source, plugin and source-config mutations remain excluded pending their effect gates. No admin rights are inferred from MCP names or descriptions. |
| Delegation | Hermes `delegate_task`; Ax child agents | Bounded inline Ax children are admitted for eligible Work, workflow and agent-job runs with scoped reads, shared budgets, cancellation and journal recovery. Separately queued children remain deferred. |

The adapter's actual admitted set lives in
`adapters/openneko/cmd/harness/main.go` and `adapters/openneko/mcp/memory.go`.
Go `Tools.admitted` validates schema and effect metadata, sorts the catalog,
hashes its binding into the checkpoint, and builds the Ax prompt from the same
admitted list. `adapters/mcp.Admit` rejects unlisted names, schema drift and
unqualified mutating effects. The host broker is a separate authorization
boundary: a forged org/run in tool arguments cannot change the token binding.
